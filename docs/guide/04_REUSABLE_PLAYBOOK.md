# دليل المهارات والأنماط الهندسية القابلة لإعادة الاستخدام
# Reusable Architecture Playbook & Project Starter Blueprint

يستخلص هذا الدليل جميع الخبرات، الأنماط البرمجية (Design Patterns)، وأفضل الممارسات الهندسية التي طُبقت في مشروع **AgriMarket**، مع تقديم **وصفة متكاملة لبدء أي مشروع ويب جديد من الصفر (Starter Blueprint)** وهيكلية مجلدات جاهزة وقالب دستور برمجيات (`PROJECT_RULES.md`) لضمان نفس مستوى الجودة والسرعة في مشاريعك المستقبلية.

---

## 1. الأنماط الهندسية المعتمدة في هذا المشروع (Design Patterns & Best Practices)

### 1. مبدأ العزل ومسؤولية المكون الفردية (Component Isolation & SRP)
- **المفهوم**: كل مكون في الواجهة مسؤول عن مهمة واحدة واضحة فقط (مثل `BrandLogo` للشعار، `TabLoader` للانتقال، `FlyToCartOverlay` للأنيميشن).
- **الفائدة**: عند الرغبة في تعديل سلوك السلة، لا يتأثر الشريط العلوي؛ وعند تعديل ألوان الشعار، يتغير تلقائياً في كل الصفحات دون لمس كود تلك الصفحات.

### 2. التطوير الموجه بالعقود (Contract-First API Alignment)
- **المفهوم**: قبل كتابة أي كود اتصال بالسيرفر، يتم اعتماد ملف العقد (`docs/AgriTech_Web_API_v1.0.yaml`) كمرجع ملزم وحيد للمسارات، أسماء الحقول، وحالات الأخطاء (مثل 422 و 401).
- **الفائدة**: يلغي التخبط بين مطوّر الواجهة ومطوّر الخادم، ويضمن أن الحقول المرسلة (`first_name`, `last_name`, `username`, `phone`) تطابق جداول قاعدة البيانات تماماً من اللحظة الأولى.

### 3. محرك التشغيل المزدوج بدون انقطاع (Zero-Disruption Mock / Live Switch)
- **المفهوم**: بناء واجهة كاملة يمكنها العمل بنسبة 100% بدون سيرفر عبر بيانات تجريبية (`USE_MOCK_API = true`)، وتتحول لنظام حي بمجرد تغيير متغير بيئة واحد (`VITE_USE_MOCK_API=false`).
- **الفائدة**: تمكين فريق التصميم والعملاء من تجربة الواجهة والتفاعل معها وتعديلها بحرية تامة حتى قبل أن يبدأ فريق الـ Backend بكتابة مسارات الـ API.

### 4. تنقية وتدقيق الحمولة البرمجية (Payload Sanitization & Defense-in-Depth)
- **المفهوم**: عدم إرسال أي حقول زائدة في طلبات الـ POST (مثل عدم إرسال أسعار المنتجات أو معرّف المشتري في طلبات إنشاء الطلب، بل إرسال `product_id` و `quantity` فقط).
- **الفائدة**: حماية النظام من ثغرات التلاعب بالأسعار (Price Tampering) والالتزام الصارم بقواعد الأمان؛ حيث يتولى الخادم الخلفي احتساب المبالغ واعتماد هوية المشتري عبر توكن التوثيق Sanctum.

### 5. إدارة الحالة المشتركة بدون تشابك (Context-Driven State Management)
- **المفهوم**: تقسيم الحالة العامة إلى سياقات وظيفية مركزة:
  - `SettingsContext` للمظهر واللغة والترجمة.
  - `AuthContext` للمصادقة وصلاحيات الجلسة.
  - `CartContext` للسلة وحسابات الأسعار وأنيميشن الطيران.
- **الفائدة**: سهولة الوصول لأي وظيفة من أي مكون في شجرة التطبيق عبر خطافات نظيفة (`useAuth`, `useCart`, `useSettings`) دون تمرير الخصائص المرهق (Prop Drilling).

### 6. هندسة طبقات الـ z-index والبوابات (createPortal Stacking)
- **المفهوم**: عزل النوافذ المنبثقة من قيود الحاويات الأب (`overflow-hidden`) عبر `createPortal(..., document.body)` وترتيب أولويات الظهور بسلم ثابت (z-40 للـ Navbar، z-100 للمنتج، z-110 للسلة، z-120 للدخول).
- **الفائدة**: استحالة حدوث قص للأطراف أو اختفاء النوافذ خلف بعضها مهما تعددت الشاشات أو تغيرت مقاساتها.

### 7. مصدر الحقيقة الموحد للبيانات الثابتة (Single Source of Truth - siteConfig.js)
- **المفهوم**: حصر وتجميع كافة بيانات هوية المنصة (الاسم، السوابق واللواحق، السطر الفرعي)، بيانات التواصل (الهاتف، الواتساب، البريد، العنوان وساعات العمل)، روابط منصات التواصل الاجتماعي، وروابط تحميل تطبيقات الهواتف في كائن مركزي واحد (`src/config/siteConfig.js`).
- **الفائدة**: الالتزام الصارم بمبدأ عدم التكرار (DRY Principle)، وتسهيل إعادة تدوير القالب لأي عميل أو مشروع جديد بالكامل في دقائق معدودة عبر تعديل ملف واحد فقط دون الحاجة لتتبع عشرات الملفات والمكونات.

## 2. وصفة بدء أي مشروع React جديد من الصفر (Starter Blueprint)

اتبعي هذه الخطوات المرتبة لبناء أي مشروع مستقبلي بنفس القوة والأداء:

### الخطوة 1: إنشاء المشروع وتثبيت أسرع حزمة بناء (Vite + React)
افتحي الطرفية (Terminal) وشغّلي:
```bash
npm create vite@latest my-awesome-project -- --template react
cd my-awesome-project
npm install
```

### الخطوة 2: تثبيت الحزم الأساسية المعتمدة
```bash
# 1. نظام التنسيق والمظهر
npm install -D tailwindcss postcss autoprefixer

# 2. أيقونات وحركات فائقة النعومة
npm install lucide-react framer-motion

# 3. فاحص جودة الكود السريع جداً (بديل ESLint فائق السرعة)
npm install -D oxlint
```

### الخطوة 3: تهيئة Tailwind CSS
```bash
npx tailwindcss init -p
```
ثم عدّلي ملف `tailwind.config.js`:
```javascript
/** @type {import('tailwindcss').Config} */
export default {
  content: [
    "./index.html",
    "./src/**/*.{js,ts,jsx,tsx}",
  ],
  darkMode: "class",
  theme: {
    extend: {
      colors: {
        primary: "#185004", // استبدلي بلون مشروعك الأساسي
      },
      fontFamily: {
        sans: ["Cairo", "sans-serif"],
      },
    },
  },
  plugins: [],
}
```

### الخطوة 4: نسخ الهيكلية المعمارية الجاهزة للمجلدات
أنشئي مجلدات `src/` كالتالي:
```text
src/
├── config/           # مصدر الحقيقة الموحد لإعدادات وهوية المنصة (siteConfig.js)
├── components/
│   ├── common/       # الشعار، الأزرار العائمة، الخلفيات
│   ├── layout/       # الهيدر، الفوتر، مؤشرات التحميل
│   └── modals/       # النوافذ المنبثقة واللوحات المنزلقة
├── context/          # سياقات إدارة الحالة المشتركة
├── data/             # قواميس الترجمة والبيانات التجريبية
├── pages/            # الشاشات الرئيسية
└── services/         # عميل الـ API ومسارات الاتصال
```

## 3. قالب دستور قواعد الكود الملزم لأي مشروع (`PROJECT_RULES.md`)

انسخي هذا المحتوى وضعيه في ملف `PROJECT_RULES.md` في جذر أي مشروع جديد لتوجيه نفسك وأي مساعد ذكي أو مطوّر يشاركك العمل:

```markdown
# دستور وقواعد المشروع (Project Clean Code Rules)

## 1. المعايير المعمارية الصارمة
- **عزل المكونات:** كل مكون مسؤول عن وظيفته فقط. يُمنع دمج منطق النوافذ المنبثقة داخل كود الصفحة الرئيسية؛ استخدم النوافذ كملفات منفصلة ومغلفة بـ createPortal.
- **عقد البيانات الموحد:** يجب أن تطابق نماذج البيانات التجريبية (mockData) والمكونات عقد الـ API المتفق عليه حرفياً في أسماء الحقول ومفاتيح الاستجابة.
- **فصل أوضاع التشغيل:** اجعل التطبيق يدعم وضع المعاينة المحلية (USE_MOCK_API) لضمان عدم توقف العمل إذا كان الخادم الخلفي غير متاح.

## 2. معايير الكود النظيف (Clean Code Standards)
- **منع الإيموجي تماماً:** يُمنع منعاً باتاً استخدام أي إيموجي (مثل 🌿، 📦، 📋، 👤) داخل الكود، أو التعليقات، أو واجهة المستخدم؛ تُستخدم أيقونات مكتبة lucide-react فقط.
- **التعليقات التوضيحية بالعربية:** اكتب تعليقاً عربياً مختصراً ومباشراً فوق كل دالة وفوق كل كتلة منطقية مهمة لتوضيح دورها بدقة.
- **تسمية المتغيرات:** استخدم أسماء إنجليزية قياسية ومعبرة بنمط camelCase للمتغيرات والدوال، و PascalCase للمكونات.
- **منع الشروط المتداخلة:** تجنب الشروط الثلاثية المتداخلة (Nested Ternaries)؛ استخدم كائنات المطابقة الثابتة (Lookup Objects).
- **التصميم المتجاوب والمريح:** صمم دائماً بمبدأ Mobile-First مع مراعاة الوضعين النهاري والليلي (dark:) واللغتين (RTL / LTR).
- **الفحص الدوري:** يجب تشغيل npx oxlint و npm run build دورياً للتأكد من خلو المشروع من أي أخطاء أو متغيرات مهملة قبل اعتماد التغييرات.
```
